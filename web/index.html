    パイプライン

    1. 型の抽出過去回のフレーム → Super VL が観察 → Ultra が統合 → style.json
    2. 台本と工程表Ultra が 4〜7工程・テロップ18字以内で生成 → バリデータ（禁止API・尺・字数）
    3. ナレーションFish Speech 1.5 zero-shot（参照30秒）→ 実測の音声長から hold_sec を更新
    4. 実行と録画Lightning の bpy コードを MCP 経由で1工程ずつ実行 → ffmpeg gdigrab でウィンドウを録画
    5. 合成ASS テロップ＋フック（赤→緑）＋音声配置 → 1080×1920 / 30fps

    Super VL によるフレーム採点と、失敗工程だけの差し戻しはスキーマとプロンプト経路まで実装済み（本番運用はこれから）。

    抽出した「型」

    41 秒尺の中央値（実測 27.8–65.0 秒 / 10本）
    9:16縦型。下1/3〜1/2がBlender画面
    18 字テロップ1枚の上限。白文字＋黒縁＋影

    型は「無理そう…（赤）→ できそう!（緑）」で始まり、1本につき操作はひとつだけ。 「全部教えない。今日ここだけ見えればいい。」がシリーズの設計です。

    実機で踏んだ罠（抜粋）

    13件のうち6件を表示
    • reasoning_effort 未指定だと思考トークンが max_tokens を食い尽くし、本文が空で返る。→ none を明示。
    • Super VL の実IDは nvidia/Nemotron-3.5-Super-VL。カタログ表記のまま投げると404。
    • viewport_screenshot はカメラレンダーで UI が写らない。→ gdigrab＋ウィンドウ矩形クロップ。
    • bpy.context.active_operator.segments は効かない。→ オペレータ呼び出しの引数で渡す。
    • MCPアドオンは stop() 直後の start() で同一ポートに LISTEN が二重に残り、接続が固まる。→ 状態を強制リセットし別ポートへ。
    • ASS の BorderStyle=3 は箱の色が OutlineColour。最初は白い空箱になった。

    全13件と、未解決事項は README に。
